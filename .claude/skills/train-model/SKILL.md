# Train & Evaluate HAR Models

Phase 4 workflow (see IMPLEMENTATION_PLAN.md §Phase 4). These rules exist so
the defense numbers survive scrutiny — do not relax them for convenience.

## Dataset assembly

1. Input: accepted sessions under `datasets/raw/` (each passed
   `/validate-session`). Group by `metadata.json` fields: label, subject,
   environment, session date.
2. Pipeline per receiver: `storage.load_amplitudes` → select
   `usable_lltf_indices()` → `hampel` → `detrend_moving_mean` (or `lowpass`;
   pick ONE config and freeze it) → `make_windows(fs=100, window_s=3,
   hop_s=1.5, max_loss=0.10)` → `align_receivers` → stack to
   `(n_windows, 3, 300, 52)`.
3. Trim transition periods at activity boundaries (first/last window of each
   session segment) — transitions are not classes in v1.

## The three mandatory splits — never report fewer

| Split | How | Purpose |
|---|---|---|
| random-window | stratified shuffle of windows | comparability with literature; inflated by temporal leakage — say so in the report |
| cross-session | hold out entire sessions (all subjects present in both sides) | honest same-people number |
| cross-subject | leave-one-subject-out, average over folds | the generalization headline; expect a drop |

Leakage rules: `fit_scaler` on the train side only, per split. Windows from
one session never straddle a split boundary. Augmentation parameters derived
from train only.

## Model ladder (in order — do not skip step 1)

1. **Classical baseline**: sklearn SVM/RF on per-window hand features
   (per-subcarrier mean/std/MAD/percentiles + 0–2 Hz / 2–10 Hz / 10–30 Hz
   spectral band energies). If a DL model can't beat this, the DL pipeline
   is broken — debug before adding capacity.
2. **CNN**: 2D conv over (time × subcarrier), receivers as input channels.
3. **CNN-LSTM**: CNN encoder per chunk → BiLSTM → head.
4. Optional: small transformer encoder (only after 2–3 work).

Adapt architectures from SenseFi (github.com/xyanchen/WiFi-CSI-Sensing-Benchmark)
rather than inventing. Keep models CPU-runnable for smoke tests; full
training on Colab/Kaggle.

## Every experiment run must produce

- A config file (YAML/JSON) committed under `experiments/configs/` — seed,
  split, preprocessing params, architecture, hyperparameters.
- A results row (CSV under `experiments/results/`): config id, split,
  accuracy, macro-F1, per-class precision/recall, **falling recall
  separately**, timestamp, git SHA.
- A confusion matrix figure generated by script into `docs/figures/`.

Fixed seeds everywhere (`numpy`, `torch`, dataloader workers). If a result
can't be regenerated by re-running its config, it doesn't exist.

## Required ablations (report chapter material)

- 1 vs 2 vs 3 receivers (drop receiver channels at assembly time)
- Window length 1/2/3/5 s
- Packet rate 25/50/100 Hz (subsample the time axis)

## Red flags — stop and investigate

- Random-split accuracy > 97%: check for duplicate/overlapping windows
  across splits before celebrating.
- Cross-subject ≈ random-split: almost certainly leakage, not brilliance.
- Falling recall high but precision terrible: check background/transition
  contamination in fall windows.
